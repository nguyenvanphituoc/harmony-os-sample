# Knowledge Base — task-executor

> Team-shared guidelines distilled by `/coach` from PO/TL feedback at the Ship Gate (L4), a
> project scan, or official-docs research. Read by `task-executor` at the top of its run.
> **Guidelines, not invariants** — they steer the worker; they never override a spec, widen a
> substrate, resolve a gate or change the spec-evaluator verdict (single-judge rule).
> Committed on purpose: a teammate inherits these on `git pull`.

## Guidelines
- **KB-TE-001** — Build with the `run_cmd` the run ledger or project profile names, from `app/` and inside a subshell (`( cd app && … )`) so your shell stays at the repo root. `hvigorw`, `ohpm` and `hdc` are not on PATH — they ship inside DevEco Studio (default macOS install `/Applications/DevEco-Studio.app/Contents/tools/…`) — so "command not found" never means the SDK is missing, and `tsc` is never a stand-in for the ArkTS build. Done means BUILD SUCCESSFUL and a fresh HAP; `assembleHap` also compiles `src/ohosTest`, so a test file that does not compile fails the whole build. Never hand-edit the generated `oh-package-lock.json5` or `app/local.properties`; change dependencies with DevEco's `ohpm`. _(why: in the hero-todo run workers concluded "no SDK in this checkout" and verified with TypeScript stand-ins that stayed green while the real build failed)_  ·  from project-scan @ b8377ad (`command -v hvigorw ohpm hdc` → not found; local hvigor build log BUILD SUCCESSFUL on node v24.11.0, 2026-09-15; `app/local.properties:1-2`); confirmed by web-research (https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ide-command-line-building-app, DevEco 6.1.1, 2026-09-15)
- **KB-TE-002** — Write ArkTS, not TypeScript. Each of these is a compile error here: `any`/`unknown`/`@ts-ignore`; untyped object literals and object-literal types; destructuring and object spread; shape-based typing (declare `implements`); index signatures, `obj[key]`, `in`, `delete`, `for..in` (use `Map`/`Record`); `as const`, literal types, `x is T`, conditional/mapped/intersection types; constructor parameter properties and uninitialised fields; function expressions, `var`, generators, `require`; `Object.assign`/`defineProperty`, `Reflect` mutators, `Proxy`. Narrow with `instanceof`; model finite sets as `enum`. Import paths are case-sensitive (`caseSensitiveCheck: true`) even though macOS is not. _(why: TypeScript allows every one of these; hero-todo's feature code hit 58 ArkTS errors in 19 files the first time it was compiled)_  ·  from project-scan @ b8377ad (`docs/index.md:259-265`, `app/build-profile.json5:13`); confirmed by web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/quick-start/typescript-to-arkts-migration-guide.md, API 24, 2026-09-15)
- **KB-TE-003** — Use ArkUI state management V2 only (`@ComponentV2`, `@Local`/`@Param`/`@Once`/`@Event`, `@ObservedV2`/`@Trace`, `@Computed`, `@Monitor`). The template `pages/Index.ets` is V1 (`@Entry @Component @State`): never copy it, never mix V1 and V2 in one tree. A child never assigns an `@Param` — it raises an `@Event`; use `@Param @Once` for seed values and `@Require @Param` for mandatory ones. Every property the UI, a `@Monitor` or a `@Computed` reads is `@Trace` inside an `@ObservedV2` class created with `new` — plain object literals are not observed. A `@Computed` getter writes no state; a `@Monitor` handler does not write the path it watches. _(why: each slip is a compile error or a screen that silently stops repainting)_  ·  from project-scan @ b8377ad (`app/entry/src/main/ets/pages/Index.ets:1-4`, `docs/ui-layer.md:70`); confirmed by web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/state-management/arkts-new-observedV2-and-trace.md, API 24, 2026-09-15)
- **KB-TE-004** — A `@Builder` repaints on state change only when it takes exactly one parameter passed as an object literal, and writing to that parameter's fields inside the builder throws at runtime. `wrapBuilder()` takes only a global `@Builder`; assigning a second `wrapBuilder` value to the same variable changes nothing — switch the registry key instead (or `mutableBuilder`, API 22+). `Repeat` needs a stable, unique, non-index `.key()` that covers every rendered field, and lazy `.virtualScroll` works only inside `List`/`ListItemGroup`/`Grid`/`Swiper`/`WaterFlow`. _(why: all of these fail silently — in the hero-todo run a row keyed by id alone stayed stale after a rename)_  ·  from project-scan @ b8377ad (`docs/ui-layer.md:131-135`); confirmed by web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/state-management/arkts-builder.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/state-management/arkts-wrapBuilder.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/rendering-control/arkts-new-rendering-control-repeat.md, API 24, 2026-09-15)
- **KB-TE-005** — `AppStorageV2` and `PersistenceV2` work on the UI thread only. `AppStorageV2` stores class types only. Use `PersistenceV2` only after the `loadContent` callback has fired; give persisted properties initial values and nested classes `@Type`. Never `connect` and `globalConnect` the same key (it crashes), and never share data between `PersistenceV2` and `Preferences`. _(why: runtime exceptions, or persistence that silently does nothing)_  ·  from web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/state-management/arkts-new-persistencev2.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/state-management/arkts-new-appstoragev2.md, API 24, 2026-09-15)
- **KB-TE-006** — A `@Concurrent` function is top-level (not an arrow function, method or generator), uses no closure or module-level variables, takes and returns serialisable values of at most 16 MB, finishes its synchronous work in under 3 minutes, and touches no UI module, `AppStorage` or `ApplicationContext`. **Unconfirmed — verify before relying:** `docs/index.md:380` places the `@Concurrent` codec in `data/*.ts`, while the official TaskPool guide says `@Concurrent` and `@Sendable` are supported only in `.ets` files. Compile one `@Concurrent` function in the layer you intend before building on it; if that placement fails, ESCALATE (`design-decision`) rather than moving layers on your own. _(why: compile or runtime failures, and TaskPool copies the UI thread never sees)_  ·  from web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/arkts-utils/taskpool-introduction.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/arkts-utils/sendable-constraints.md, API 24, 2026-09-15)
- **KB-TE-007** — No user-visible text, hex colours or bare sizes in `.ets` or `.ts`: reference `resources/` through `$r(...)` and type text and colour props as `Resource`. Every `$r` key you use must exist in `resources/base/element/` and in each qualifier folder (`dark/`, each locale) — a missing key fails the build or renders blank. **Unconfirmed — verify before relying:** `docs/ui-layer.md:476` says a file under `element/` with a non-standard name is silently not compiled, while the official resource guide calls the standard names recommended and makes one data type per file the hard rule; keep the standard names (`string.json`, `color.json`, `float.json`, `plural.json`) either way. _(why: in the hero-todo run uikit tokens and error messages referenced keys that did not exist)_  ·  from project-scan @ b8377ad (`docs/ui-layer.md:93-97,475-477`); web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/quick-start/resource-categories-and-access.md, API 24, 2026-09-15)
- **KB-TE-008** — `entry` is an ArkUI-X cross-platform module (`app/.arkui-x/arkui-x-config.json5:2`, `app/hvigorfile.ts:2`): any API missing from ArkUI-X's cross-platform list fails `CompileArkTS` with 11706007 "can't support crossplatform application" — in `src/ohosTest` as well. HMS kits such as Remote Communication Kit (`rcp`) are not cross-platform. Never set `ignoreCrossPlatform` to get past it (the compile error becomes a crash on Android/iOS); ESCALATE (`design-decision`) with the error instead. _(why: the hero-todo ohosTest suite failed to compile on 11706007 bans — UiTest `waitForComponent`, `abilityDelegatorRegistry`)_  ·  from project-scan @ b8377ad; confirmed by web-research (https://gitee.com/arkui-x/docs/blob/master/zh-cn/application-dev/quick-start/platform-different-introduction.md, ArkUI-X API 24, 2026-09-15)
- **KB-TE-009** — This project fails the build on its own house rules, before any compile. `app/hvigorfile.ts:9` and `app/entry/hvigorfile.ts:11` both call `runEnforce(<app/>)` at hvigorfile **module-evaluation** time, so the L1–L11 table in `app/build-src/enforce/rule-table.ts` runs on *every* hvigor invocation — `assembleHap`, `test`, `onDeviceTest`, `clean`, all of them — and one error-severity hit throws before hvigor reaches a single task (`enforce/index.ts:32-40`). Six error rules can actually bite in this tree: **L1** no hex literal `#[0-9a-fA-F]{3,8}` in any `.ets`; **L3** no quoted literal inside `Text(…)`, `.label(…)` or `.placeholder(…)` — use `$r(...)`/`ResourceStr`; **L6** route map ↔ `@Builder` (KB-TE-010); **L7** no `getStringSync(` *anywhere* (the allow-list path is dead, so no location is exempt — go through the uikit i18n helpers); **L8** no `LazyForEach`, use `Repeat`; **L9** no `@Provider`/`@Consumer`. Every check is a plain regex over raw file text with no comment stripping (`enforce/fs-scan.ts:71-83`), so a hex colour or a `Text('…')` **inside a comment** fails the build exactly like real code, and the walk covers `src/test` and `src/ohosTest` too. Run the project's `run_cmd` after any `.ets` edit — this table is why a "trivial" change turns the whole build red. _(why: an error-level hit is indistinguishable from a compile failure at the call site and blocks every target, so it costs a whole round if you find it at verify time instead of at edit time)_  ·  from project-scan @ 8ff364a (working tree)
- **KB-TE-010** — Rule **L6** in detail, because it is the one that has already cost a round. `routeMapMatchesPages` (`app/build-src/enforce/scan.ts:151-181`) compares `route_map.json`'s `buildFunction` values against the `@Builder` functions it can find, **in both directions** — an unmatched name on either side is an error. It has two traps, and find-my-todos hit both at once: (1) it only reads files whose name ends in `Page.ets` (`scan.ts:163`, `listFilesWithExt(root, "Page.ets")`), so a builder declared in `TodoList.ets` is invisible no matter how correct the route entry is — name a routed screen's file `<Screen>Page.ets`; (2) the declaration regex is `/@Builder\s+function\s+([A-Za-z0-9_]+)/` (`scan.ts:168`), so **an `export` keyword between `@Builder` and `function` defeats it** — `@Builder\nexport function TodoListBuilder(…)` matches nothing and the builder counts as undeclared even in a correctly named file. Declare it bare (`@Builder function <Screen>PageBuilder(name: string, param: object) { … }`) and export it on a separate line. The route map it reads is `app/entry/src/main/resources/base/profile/route_map.json`. _(why: find-my-todos escalated at `find-my-todos-screen-r1-a1` — both T0 fixtures exited 1 on `enforce: 1 error-level §5 rule violation(s) … [L6] route_map.json:1`, and every `hvigorw` target stayed red for the rest of the round)_  ·  from project-scan @ 8ff364a (working tree)
- **KB-TE-011** — Never edit `app/build-src/enforce/rule-table.ts`, `app/build-src/enforce/scan.ts`, `app/hvigorfile.ts` or `app/entry/hvigorfile.ts` to get past a rule — not lowering a `severity` to `warning`, not narrowing a `scanPattern`, not deleting a `RULE_TABLE` row, not commenting out a `runEnforce(…)` call. When a rule blocks an acceptance criterion you cannot satisfy inside your substrate, ESCALATE (`design-decision`) naming the rule id, its `checkId`, the `file:line` of the check and the AC it blocks, and stop there. _(why: that table is the project's own build contract, and a worker that edits its grader turns the build green while the defect ships — find-my-todos' executor escalated instead of relaxing L6, which is the behaviour to repeat)_  ·  from project-scan @ 8ff364a (working tree)
- **KB-TE-012** — A new `*.test.ets` file runs only if its tier's suite entry imports it: `app/entry/src/test/List.test.ets` for `hvigorw test`, `app/entry/src/ohosTest/ets/test/List.test.ets` for `hvigorw onDeviceTest`. Each is a one-line `import x from './X.test'` plus a call to `x()` inside `export default function testsuite()`. An unregistered test file still compiles, so the build stays green and the suite simply never runs it — any fixture or AC citing that test is green over nothing. Register the file in the same change that adds it; if the suite entry is outside your substrate, ESCALATE rather than reporting the test as passing. _(why: find-my-todos wrote `TodoSearch.test.ets` and `FindMyTodosIntegration.test.ets`, but `src/test/List.test.ets` imports only `LocalUnit.test` — neither new suite would have run even once the L6 block cleared)_  ·  from project-scan @ 8ff364a (working tree)
- **KB-TE-013** — For every device-tier Test Surface row of your scope's use cases, write `device-flows/<scope_id>/<TS-id>.flow` — one file per row, named by the row's id — asserting the row's Expect in the flow language documented at the top of `scripts/ui-flow.sh` (`launch`, `tap`, `type`, `back`, `expect text|no text|count|order`). This is the only on-device test form here: `entry` is an ArkUI-X cross-platform module and the build rejects in-app UiTest (`Driver`, `abilityDelegatorRegistry`, error 11706007). Give every control a flow must press an `.id(...)`, so a flow does not depend on display text alone. A red flow prints `FAIL <TS-id> step N: <why>` — fix the code, not the flow, unless the flow misreads the row. _(why: without flows the judge saw only the first screen and the fix rounds starved)_  ·  PO decision at COACH-1, 2026-09-26; measured on the Pura 90 emulator 2026-09-26: `scripts/ui-flow.sh` ran three flows in 19 s, two real passes (V2 order, V3 toggle and count) and one deliberate failure reported with the text on screen
- **KB-TE-014** — A list item's decorative layer — a shadow, a backdrop — never sizes itself `height('100%')`. Inside an unconstrained `List` that resolves to the viewport, so one card's shadow covers the whole list and every other card is off screen. Draw a hard shadow as the face's margin over an ink-coloured container instead. _(why: two independent builds of the retro card made exactly this mistake; the second time a verdict round was spent finding it)_  ·  PO decision at COACH-1, 2026-09-26; seen in builds on two branches, 2026-09-25 and 2026-09-26
