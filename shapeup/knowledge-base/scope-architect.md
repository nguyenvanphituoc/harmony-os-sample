# Knowledge Base — scope-architect

> Team-shared guidelines distilled by `/coach` from PO/TL feedback at the Ship Gate (L4), a
> project scan, or official-docs research. Read by `scope-architect` at the top of its run.
> **Guidelines, not invariants** — they steer the worker; they never override a spec, widen a
> substrate, resolve a gate or change the spec-evaluator verdict (single-judge rule).
> Committed on purpose: a teammate inherits these on `git pull`.

## Guidelines
- **KB-SA-001** — Give each **registration** file exactly one owning scope — the files where code becomes reachable or runnable, which no feature substrate owns by default:
  - *Wiring*: `app/entry/src/main/module.json5` (`srcEntry`, `routerMap`, `appStartup`), `route_map.json` and every `pageSourceFile` it names, `startup_config.json` and its task files, the `EntryAbility`, the `Navigation` host page, the `AppModules` container, `oh-package.json5` with its lockfile, and `build-profile.json5`.
  - *Test registration*: the two suite-entry files, `app/entry/src/test/List.test.ets` (unit tier) and `app/entry/src/ohosTest/ets/test/List.test.ets` (instrumented tier). A `*.test.ets` the entry does not import compiles and never runs, so a scope that writes tests but cannot edit its tier's entry ships a fixture that is green over nothing.
  - *Build enforcement*: `app/build-src/enforce/**` and both `hvigorfile.ts` files. Give them one owner (or no owner) deliberately — never leave them incidentally inside a feature scope's substrate, since editing them is how a worker makes a red build green without fixing anything (KB-TE-011).

  _(why: in the hero-todo run no scope owned `module.json5`'s routerMap, the page files, `startup/**` or the DI container, and the app launched blank; in find-my-todos the screen scope owned its two new test files but not `src/test/List.test.ets`, and escalated with the tests written and unrunnable)_  ·  from project-scan @ b8377ad (`app/entry/src/main/module.json5:12-16`, `app/entry/src/main/resources/base/profile/main_pages.json:3`, `app/entry/src/main/ets/entryability/EntryAbility.ets:20`), extended @ 8ff364a (working tree) (`app/entry/src/test/List.test.ets:1-5`, `app/hvigorfile.ts:9`, `app/entry/hvigorfile.ts:11`)
- **KB-SA-002** — `resources/base/element/{string,color,float}.json` — plus their `dark/` and per-locale copies — cannot be split per screen, and every UI scope adds keys to them. Give them to one scope the UI scopes depend on, or state up front that the scopes touching them build one at a time. _(why: two scopes editing one file concurrently drop each other's changes — AGENTS.md, "Your scope cut decides your concurrency")_  ·  from project-scan @ b8377ad (`docs/ui-layer.md:476-477`)
- **KB-SA-003** — A fixture that claims the code compiles or a screen is reachable runs the project's hvigor build (the run's `run_cmd`) or the launch probe — never `tsc`, a grep of source text, or a check that pins verbatim implementation code. _(why: all 30 hero-todo T0 trials were green while the real build failed)_  ·  from project-scan @ b8377ad
- **KB-SA-004** — Keep `app/.arkui-x/**` out of every scope's substrate unless a pitch targets Android or iOS: it is a generated shell with Gradle cache files committed to git and another developer's SDK path (`app/.arkui-x/android/local.properties:7`). _(why: a worker "fixing" it breaks the cross-platform shell for everyone)_  ·  from project-scan @ b8377ad (`git ls-files app/.arkui-x`)
- **KB-SA-005** — **WITHDRAWN 2026-09-26 (PO, COACH-1).** It said to slice scopes along `features/<context>/**` — a directory cut, which spec-lint rule PA1 refuses ("slice by flow, not by directory"), so following it aborted a run at L1b. Superseded by KB-SA-007.
- **KB-SA-006** — A fixture that runs `hvigorw onDeviceTest` must turn red when a test fails or the build fails. hvigorw exits 0 on a failing case, and it colours its output even into a pipe (`> hvigor ESC[91mERROR: …`), so a search for `hvigor ERROR` never matches. Keep hvigorw's own exit code and search for `ERROR:`: `out=$( ( cd app && DEVECO_SDK_HOME=/Applications/DevEco-Studio.app/Contents/sdk /Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw onDeviceTest -p module=entry -p coverage=false --no-daemon ) 2>&1 ); rc=$?; echo "$out" | tail -20; [ "$rc" -eq 0 ] && ! echo "$out" | grep -q 'ERROR:'`. _(why: 4 of retro-todo's 8 scopes had a bare `hvigorw onDeviceTest` as their only fixture; the first form of this rule searched for `hvigor ERROR` and was green over a failing test and over a failed build)_  ·  from a device check @ d4da2fa (Pura 90 emulator, DevEco 6.1.1, 2026-09-16: one deliberately failing case → exit 0 and `Tests run: 2, Failure: 1` on the device; the corrected check, replayed on the raw logs, is red on the failing test and on a failed build and green on two passing runs)
- **KB-SA-007** — Cut scopes along the breadboard's V# slices, never along directories or layers. A scope is one V# slice, or two adjacent ones, and owns every use case that slice demos — its domain code, its UI and its tests travel together in that scope. Record the V# a scope delivers in its contract. Each shared file (`resources/base/element/*.json`, `pages/Index.ets`) has exactly one owning scope, and every other scope that needs it `depends_on` that owner rather than writing it. _(why: the breadboard's V1–V6 table is the pitch's own flow cut. Cut by layer — tokens, domain, tests, kit, shell, screens — every task was claimed by three to seven scopes (SCOPE-PARTITION red on all 18) and every substrate aligned to one directory (PA1 red); cut into a single scope, concurrency and substrate disjointness were never exercised)_  ·  PO decision at COACH-1, 2026-09-26; replaces KB-SA-005
- **KB-SA-008** — A scope whose use cases carry device-tier Test Surface rows owns `device-flows/<scope_id>/**` in its `allowed_file_substrate` and declares `./scripts/ui-flow.sh device-flows/<scope_id>` as a fixture, after `./scripts/t0-assemble.sh` so it drives this build. The directory per scope keeps flows disjoint by construction. _(why: device rows were graded NO EVIDENCE in every round of the convergence run because nothing in any scope drove the app — the fix rounds received no bugs and had nothing to fix; a flow fixture makes each row a pass or a named failure inside the scope's own attempt loop)_  ·  PO decision at COACH-1, 2026-09-26; measured on the Pura 90 emulator 2026-09-26: `scripts/ui-flow.sh` ran three flows in 19 s, two real passes (V2 order, V3 toggle and count) and one deliberate failure reported with the text on screen
