## Guidelines
- **KB-QA-001** — **Unconfirmed — check on the device:** `docs/ui-layer.md:672` says `fp` text follows the system font size, while the official app configuration reference says `configuration.fontSizeScale` defaults to `nonFollowSystem` — and `app/AppScope/app.json5` sets no `configuration`. Probe at the largest system font (`fontSizeMaxScale` defaults to 3.2): report whether text scales at all, and where it does, whether containers with a fixed height clip it. _(why: an app that ignores the system font size passes every visual check at the default size)_  ·  from project-scan @ b8377ad (`app/AppScope/app.json5`); web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/quick-start/app-configuration-file.md, API 24, 2026-09-15)
- **KB-QA-002** — **Unconfirmed — check on the device:** `docs/ui-layer.md` §2.5 pauses media and sensors in `onWillHide`, while the official NavDestination guide says `onWillHide` does not fire when the app goes to the background, and `onShown` fires on every return to the foreground. Probe: background the app mid-screen — does anything keep running? Bring it back — does the screen flash, reload or load twice? _(why: resources that keep running in the background and refreshes that fire more often than designed are both invisible in a foreground-only walkthrough)_  ·  from web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/ui/arkts-navigation-navdestination.md, API 24, 2026-09-15)
- **KB-QA-003** — Probe state that outlives what it should, or does not survive what it should: a cold start after an in-app language change (the official i18n guide says the language persists, and `'default'` clears it only after a restart); `hdc install -r`; kill-and-relaunch deep in the navigation stack (the team docs say the stack restores itself, the official docs say only with `recoverable(true)` — unconfirmed, report what you see); an in-app language switch while three screens deep (the docs are silent on screens already in the stack, `docs/ui-layer.md` §8 U4); dark mode. _(why: the hero-todo app came up in Vietnamese on a later launch, a leftover of an earlier run)_  ·  from project-scan @ b8377ad (`docs/ui-layer.md:553-568,804`); web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/internationalization/i18n-preferred-language.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/arkui-ts/ts-basic-components-navigation.md#recoverable14, API 24, 2026-09-15)
- **KB-QA-004** — A blank white page with only a back arrow after launch is an empty `NavDestination`: the route did not resolve, and hilog shows `can't find name in config file` then `load page failed`. After every launch, read hilog (`hdc shell hilog -x -L E`) and check `/data/log/faultlog/faultlogger` for new `jscrash-`/`cppcrash-`/`appfreeze-` files — not only when something visibly crashes. _(why: the hero-todo build was green while the app launched blank)_  ·  from web-research (https://gitee.com/openharmony/docs/blob/master/en/application-dev/dfx/jscrash-guidelines.md, https://gitee.com/openharmony/docs/blob/master/en/application-dev/tools/aa-tool.md, API 24, 2026-09-15)
- **KB-QA-005** — Hunt against the live component tree, not only the screen. `hdc shell uitest dumpLayout -p /data/local/tmp/layout.json -b <bundle>` then `hdc file recv` returns the running app's tree as JSON — every node's `type`, `text` and bounds — and `uitest screenCap -p <path>` grabs the matching PNG. Both ship in the SDK already on this machine (`…/sdk/default/openharmony/toolchains/hdc`); nothing needs installing. Use the tree for what a screenshot cannot show: a node rendered with empty text, a control present but zero-sized, two nodes claiming the same bounds, a tree that is up but has no text in it at all. The launch probe writes both to `.shapeup/launch-probe/` on every round, so the previous round's tree is there to diff against. _(why: fifteen `[ui]` criteria were graded "NO EVIDENCE on running app" across four soaks while the instrument to evidence them was already installed and unused)_  ·  measured on target `127.0.0.1:5555` during the retro-todo 3.9.2 soak, 2026-09-25 (6 text-bearing nodes returned from the running feature)
