# UC-01 — Create a list

Actor: the user, on P1 Lists (opens P3 List Name Dialog, Create mode). Covers R1.

## Input / Output

- Input: `name: string`
- Output: `Result<TodoList>` — `Ok(list)` or `Err(LIST_NAME_EMPTY)`

## Steps

1. The user taps "+ NEW LIST" (U1) or "CREATE YOUR FIRST LIST" (U6); `ListsViewModel.onNew()` (N16) opens P3 titled "NEW LIST" (U16).
2. The user types a name (U17) and taps "SAVE" (U19); `ListNameForm.submit()` (N20) calls `CreateList(name)` (N6).
3. `CreateList` calls `TodoRules.checkListName` (N4); on `Ok` it calls `InMemoryTodoRepository.createList` (N12), which writes S1.
4. On `Ok` the dialog closes and the new list is the first card on P1 (newest-created first). On `Err` the dialog stays open and shows "Name can't be empty" (U18).
5. "CANCEL" (U20) closes P3 and changes nothing.

## Invariants

- [INV-01] A name that is empty or whitespace-only after trim never creates a list (R1).
- [INV-02] Duplicate names are allowed: creating "Travel" twice yields two lists (R1).
- [INV-03] The stored name is the trimmed name.

## Error Cases

| Code | When | Message / action |
|---|---|---|
| `LIST_NAME_EMPTY` | name blank after trim | "Name can't be empty" at the field; dialog stays open |

## System Flow

`U19 -> N20 ListNameForm.submit -> N6 CreateList -> N4 TodoRules -> N12 repository -> S1 -> N14 cards -> U2`
