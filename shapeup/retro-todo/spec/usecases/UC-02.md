# UC-02 — Rename a list

Actor: the user, on P1 Lists (opens P3 in Rename mode). Covers R16.

## Input / Output

- Input: `listId: string`, `name: string`
- Output: `Result<TodoList>` — `Ok(list)`, `Err(LIST_NAME_EMPTY)` or `Err(LIST_NOT_FOUND)`

## Steps

1. The user taps the rename icon (U4) on a list card; `ListsViewModel.onRename(listId)` (N18) opens P3 titled "RENAME LIST" (U16) with the name field pre-filled (U17).
2. The user edits the name and taps "SAVE" (U19); `ListNameForm.submit()` (N20) calls `RenameList(listId, name)` (N7).
3. `RenameList` calls `TodoRules.checkListName` (N4); on `Ok` it calls `InMemoryTodoRepository.renameList` (N12), which writes S1.
4. On `Ok` P3 closes and the card shows the new name; the list keeps its place and its items. On `Err` P3 stays open with "Name can't be empty" (U18).

## Invariants

- [INV-04] A blank name never renames a list; the old name is kept (R16).
- [INV-05] Renaming changes only `name`: `id`, `createdAt` and the list's items are untouched.

## Error Cases

| Code | When | Message / action |
|---|---|---|
| `LIST_NAME_EMPTY` | name blank after trim | "Name can't be empty" at the field |
| `LIST_NOT_FOUND` | the id no longer exists | returned as `Err`; no state change |

## System Flow

`U4 -> N18 onRename -> P3 -> U19 -> N20 submit -> N7 RenameList -> N4 -> N12 -> S1 -> N14 -> U2`
