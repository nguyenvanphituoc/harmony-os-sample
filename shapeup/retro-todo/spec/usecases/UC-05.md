# UC-05 — Toggle an item

Actor: the user, on P2 List. Covers R6, R7, R8.

## Input / Output

- Input: `itemId: string`
- Output: `Result<TodoItem>` — `Ok(item)` with `done` flipped, or `Err(ITEM_NOT_FOUND)`

## Steps

1. The user taps anywhere on an item card (U13); `ListViewModel.onToggle(itemId)` (N25) calls `ToggleItem(itemId)` (N10).
2. `ToggleItem` calls `InMemoryTodoRepository.setDone` (N12) with the flipped value, writing S2.
3. Marking done: the item joins the done group at once, at its creation-order place in that group (newest-created first within the group), below every open item. Its text is struck through in `inkMuted` on `surfaceDone`, and the box is checked (U12).
4. Marking not done: the item returns to its creation-order place among the open items (newest-created first) and renders as an open card.
5. P1 progress counts follow (for example Groceries "1/3 done" becomes "2/3 done").

## Invariants

- [INV-10] Done items always sit below every open item (R7).
- [INV-11] Within each group the newest-created item comes first; toggling never moves an item to the top of a group unless it is the newest-created there (R7).
- [INV-12] A done item is struck through and changes color, so the difference never rests on color alone (R8).
- [INV-13] The move is instant; there is no reorder animation (No-go).

## Error Cases

| Code | When | Message / action |
|---|---|---|
| `ITEM_NOT_FOUND` | the id no longer exists | `Err`; no state change |

## System Flow

`U13 -> N25 onToggle -> N10 ToggleItem -> N12 setDone -> S2 -> N22 -> N5 ItemOrder -> U12` and `S2 -> N14 -> U2` (progress)
