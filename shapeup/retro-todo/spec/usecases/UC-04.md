# UC-04 — Add an item

Actor: the user, on P2 List. Covers R5.

## Input / Output

- Input: `listId: string`, `title: string`
- Output: `Result<TodoItem>` — `Ok(item)`, `Err(ITEM_TITLE_EMPTY)` or `Err(LIST_NOT_FOUND)`

## Steps

1. The user types a title in the new-item field (U9) and taps "ADD" (U10) or submits from the keyboard; `ListViewModel.onAdd()` (N24) calls `AddItem(listId, title)` (N9).
2. `AddItem` calls `TodoRules.checkItemTitle` (N4); on `Ok` it calls `InMemoryTodoRepository.addItem` (N12): a new open item with `createdAt` now is written to S2.
3. On `Ok` the field is cleared and the new card is the first open card (newest-created first). If the list had been empty, the invitation (U15) is gone.
4. On `Err` the field keeps its text and shows "Title can't be empty" (U11).

## Invariants

- [INV-08] A title that is empty or whitespace-only after trim never creates an item (R5).
- [INV-09] A new item starts open and belongs to the list it was added in only (R3).

## Error Cases

| Code | When | Message / action |
|---|---|---|
| `ITEM_TITLE_EMPTY` | title blank after trim | "Title can't be empty" at the field (U11) |
| `LIST_NOT_FOUND` | the list vanished | `Err`; no state change |

## System Flow

`U10 / U9 -> N24 onAdd -> N9 AddItem -> N4 -> N12 -> S2 -> N22 items -> N5 ItemOrder -> U12`
