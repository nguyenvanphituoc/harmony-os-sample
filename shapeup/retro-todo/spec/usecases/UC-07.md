# UC-07 — View the lists

Actor: the user, on P1 Lists (the root screen). Covers R0, R2, R11, R14, R15.

## Input / Output

- Input: none (reads S1 and S2)
- Output: list cards, newest-created first, each with name and progress; or the empty invitation

## Steps

1. Cold start: `EntryAbility` loads `pages/Index` (N1); `Index` builds the `Navigation` host and `TodoModule` (N2, N3); the repository seeds S1 and S2 (N13).
2. P1 shows Loading for the first frame, then Ready (N15). `ListsViewModel.cards` (N14) yields one card per list, newest-created first, with progress "<done>/<total> done" or "No items" when the list is empty (U2).
3. When S1 is empty (for example after deleting every list) `status` is Empty and P1 shows "No lists yet" with "CREATE YOUR FIRST LIST" (U6), which opens P3 (UC-01). Never a blank screen.
4. Tapping a card body (U3) opens that list (UC-08). Rename and delete icons (U4, U5) start UC-02 and UC-03.
5. Every list is its own card (`RetroCard`, `surface`).

## Invariants

- [INV-17] Every cold start begins with the same seed: Groceries 1/3 done, Work 1/2 done, Weekend "No items", in that order; nothing survives a restart (R14).
- [INV-18] With no lists P1 always shows the invitation, never a blank screen (R0).
- [INV-19] A card's progress is derived from S2 for that list only: done items / all items (R2).
- [INV-20] The Error branch of `status` exists with no trigger; in-memory data cannot fail (No-go: no Loading/Error demo switch).

## Error Cases

None reachable. The Error branch renders through `AsyncBoundary` but nothing sets it.

## System Flow

`N1 -> N2 -> N3 -> N13 seed -> S1 + S2 -> N14 cards / N15 status -> U2 / U6`
